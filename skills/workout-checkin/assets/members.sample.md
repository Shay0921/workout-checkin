# members.json 字段说明书（首次初始化配套）

本文件是 `assets/members.sample.json` 的使用说明，**只给 AI 读**，用于首次初始化配置时向用户提问、生成 `<工作区>/members.json`（工作区根目录，与 records.json / data.json / reports/ 同级；**不要写进 skill 目录**）。

> 结构真源 = `assets/members.sample.json`；填写口径真源 = 本文件。
> **不要把示例值直接当成品**：`group`、`periodConfig` 的 `YYYY-MM-DD`、`nickname` 三处占位符必须替换，`preflight.mjs` 会拦截未替换的占位符。

---

## 一、字段分档（哪些必须问、哪些有默认值）

| 档位 | 字段 | 说明 |
| --- | --- | --- |
| **必须问（只问这三件）** | `group`、成员名单（从用户贴的接龙里提取）、`periodConfig`（首个统计周） | 缺任一项无法计算或期号错乱 |
| **默认值直出（列摘要给用户，「不调整就按默认来」）** | `weekRule.minCheckins`（默认 3）、`redPacket`（默认 ¥10 / ¥5）、`leaveKeywords`（默认 9 词）、`defaultWeightKg`（默认 60） | sample.json 里的默认值开箱即用，用户有异议再改 |
| **可选提供（用户愿意就给，不提供全默认）** | `members[].weightKg`、`members[].gender`、`members[].aliases` | 体重影响卡路里绝对值（缺省 60kg 够用）；性别只影响文案/头像色、零计算影响；别名先从接龙原文观察 |
| **可自选改（用户随时可调）** | `met`、`sportAlias`、`sportNickname`、`intensityOverride`、`weekRule.minCheckins`、`redPacket`、`leaveKeywords` | 改完直接重跑 calc 生效，无需改脚本 |
| **一般别动** | `convert`（除新增折算项目外）、`badges` | `convert` 存的是「楼层/公里/个数 → 分钟」的折算系数，sample.json 已带群内常用口径（见第三节）；`badges` 是成就阶梯，改了会让历史叠加跳档 |

## 二、量纲折算（`convert`）：先问再算，问完写回配置

接龙里出现 `floor` / `km` / `count` 这类**折算单位**时，分钟数由 `convert` 决定。规则只有一条：**配置里有这个项目的系数就直接算，没有就先问用户，问到的结果写进 `<工作区>/members.json` 的 `convert`，然后才跑 calc**——禁止借用别的项目的系数（km 早期只有游泳，套到跑步/骑行上整期时长与卡路里全错）。calc 遇到未配置的项目会报「公里/数量/楼层换算未配置」并点名项目与配置键，照报错文案问即可。

| 单位 | 配置字段 | 含义 | sample.json 默认 |
| --- | --- | --- | --- |
| `h` | —— | 小时 × 60 | 无需配置 |
| `min` | —— | 原值 | 无需配置 |
| `floor` | `convert.climbPerFloorMin` | 每层几分钟 | `0.4`（33 层 ≈ 13min） |
| `km` | `convert.kmPerMin[标准项目名]` | 每公里几分钟（配速） | `游泳 30` · `跑步 6` · `骑行 3` |
| `count` | `convert.minPerCount[标准项目名]` | 每个动作几分钟 | `跳绳 0.01`（1000 个 ≈ 10min） |

- **游泳固定 `1 km ≈ 30 分钟`**（sample 与工作区配置统一按此口径），换算写在 `kmPerMin.游泳`；`convert.swimPerKmMin` 不是有效字段，calc 不读取，留在配置里会被 preflight 当成「不生效的未知键」提示。
- `kmPerMin` / `minPerCount` 的键必须是 `met` 里的**标准项目名**（别名先被 calc 归一，再查系数）；写了不在 `met` 里的键 preflight 会告警。
- 群内新增折算项目（如「徒步 5km」「划船机 10km」）→ 问用户口径 → 加一行系数 → 重跑 preflight 与 calc。**用户给的系数是长期口径**，写进配置后下期直接复用，不必每周重问；用户主动说「这次特殊」才临时换算成 `min` 填 records。
- 只改系数会改变**历史口径**：归档是不可变快照、不回溯重算，之后各期按新系数走。

## 三、向用户提问的方式（默认值优先，一条消息问完）

**不要按字段逐项提问**。先一句话列默认值摘要（达标线 3 次/周 · 红包差 1 次 ¥5 / 差 2 次或未打卡 ¥10 · 请假词默认 9 个 · 体重默认 60kg），声明「不调整就按默认来」，然后只问三件事：

1. **群名**：直接抄微信里的群名（可含 emoji）。
2. **成员名单**：最省事 = **直接贴一次完整接龙**，名单从接龙里提取（原样保留 emoji、波浪号）；没有接龙时，一行一个昵称的纯名单也可以。**⚠ 接龙只覆盖已打卡的人，是名单下界**——提取后必须补问一句「群里还有没有未打卡/请假没接龙的成员？」，补全到群的实际人数再写盘；否则第 1 期红包/达标率按缺员计算且不可回溯。体重/性别可选：按「昵称 体重 性别」附在名单后（如「某成员 52 女」），不提供一律默认 60kg / 性别留空。**要主动讲清**：① 卡路里由体重决定（默认 60kg 会整体略偏），性别不影响卡路里、只影响文案/头像色；② 周报 HTML/JSON 归档是不可变快照、不会自动重算——后期改体重只对之后各期生效，坚持重算历史需把往期打卡记录全部重跑一遍（期数越多越慢）。同一个人的其他写法（改名、带后缀备注）从接龙原文观察，观察不到先不配 `aliases`。**成员清单摘要（昵称/体重/性别，缺省值标明）先给用户过目再写盘。**
3. **首个统计周**：常规周填周一 ~ 周日；首期从周内某天开始（节后短周、周五开统等）填**实际开始日 ~ 该周周日**（如国庆后 `2026-10-08 ~ 2026-10-11`、周五起统 `2026-10-16 ~ 2026-10-18`），`anchorIssue` 一般填 1。**不要把锚点改成该周周一**——calc 按锚点所在自然周推期号，填周一会把首期长度虚报成整周；首期达标线用 `--min-checkins N` 临时调整。

确认后写盘到 `<工作区>/members.json`，重跑 preflight（退出码 0）。

### 接龙格式（初始化时告知用户，不是强约束）

接龙由 AI 逐条翻译，**不是死格式解析**——每行含「昵称 + 项目 + 数量单位（或请假原因）」即可，行首序号、次数标注、加号分隔、一条多项目都能识别。两种典型写法：

格式 A（推荐给新群，信息最规整）：

```
#运动打卡# 第 N 周
1. 昵称 第1次 跑步 30min
2. 昵称 第2次 爬楼梯 22层
3. 昵称 游泳 1.5km
4. 昵称 病假
5. 昵称 第三次请假
```

格式 B（群里已有习惯，照常沿用，不要要求改格式）：

```
#接龙
10.12-10.18 每日运动打卡
1. 昵称 自由活动+46分钟+羽毛球+1.85h+本周第一次打卡
2. 昵称 本周病假
3. 昵称+力训+40分钟+本周第①次打卡
```

通用要点：每行一个成员；「第N次 / 第①次 / 第一次」可省略（calc 自动补号）；一条多项目自动拆条；请假要区分两种：整周请假只写原因（命中请假词即整周豁免）；按次请假要注明次数（如「第三次请假」），翻译时加 `times`（见下方「请假写法」）。写公里/楼层/个数时按接龙原样写数值与单位即可，折算系数走 `convert`（见第二节）。**群里有现成格式就直接沿用**；只有没有固定格式的新群才把格式 A 模板发到群里。下周起用户把接龙原文贴进来就是 Step 1 的输入。

### 请假写法（整周 vs 按次）

| 原文 | records.json 写法 | 含义 |
| --- | --- | --- |
| 「本周病假」「复查」「考试」 | `{ "nickname": "昵称", "reason": "病假" }` | **整周豁免**：本周不承担打卡义务，不进未达标名单，红包 ¥0 |
| 「第三次请假」「请假两次」「第 2 次病假」 | `{ "nickname": "昵称", "reason": "第三次请假", "times": 1 }` | **按次请假**：占用第 3 个打卡名额，只抵 1 次义务；请假 N 次填 `times: N` |

- 「第三次请假」不是 `times: 3`：第 3 次是名额序号，实际只请了 1 次。
- 按次请假只用于**未注明整周**的语义；整周请假误加 `times` 会把豁免的人拖进未打卡名单。
- 打卡次数 + 请假次数 ≥ 达标线即达标（名单显示「达标+N请假」）；0 打卡且请假次数 ≥ 达标线，按整周豁免处理；否则按未打卡或差 N 次计。
- 部分请假成员仍进打卡名单；打卡不足但有效次数达标时显示「达标+N请假」，**不会出现在 `leaveList`**——`leaveList` 只放整周请假。

## 四、`members[]` 逐字段填写说明

| 字段 | 填什么 | 注意 |
| --- | --- | --- |
| `nickname` | **接龙里的原始写法**（显示名） | 改名时把新名换进这里，旧名进 `aliases`，新旧都永久有效；历史累计/连击按别名接续，不清零 |
| `aliases` | 该成员的其他写法数组，可空 | 归一化后全等匹配 + 唯一前缀兜底；前缀命中多人时 calc 报错，靠 aliases 补准 |
| `status` | `active` / `left` | 退群改 `left`：不再参与统计与红包，但历史累计保留 |
| `weightKg` | 数字，单位 kg；**可整字段省略** | 省略即按顶层 `defaultWeightKg`（默认 60）换算卡路里（`MET × 体重 × 时长`）。`defaultWeightKg` 必须是正数——两者都没有时 calc 报「体重缺失」并点名成员，不会静默按 0 算。**改体重只对之后各期生效**，历史归档不回溯 |
| `gender` | `男` / `女` / `""` | 仅影响文案措辞与头像色，可留空。修改无任何计算影响 |

## 五、可自选修改的项（用户日后想调整时改这里）

| 想改什么 | 改哪个字段 | 生效方式 |
| --- | --- | --- |
| 达标线（如本周只要求 2 次） | 临时用 `--min-checkins 2` 传参；长期改 `weekRule.minCheckins` | calc 重跑即生效 |
| 红包金额 | `redPacket.zeroOrOne` / `redPacket.two` | 重跑即生效 |
| 请假词 | `leaveKeywords` 增删 | 重跑即生效；用于识别请假语义，整周/按次由 records.json 是否带 `times` 决定 |
| 加一项新运动 | `met` 加 `"项目名": MET值`；`sportNickname` 配专精昵称；`sportAlias` 补别名（标准名放键、口语放值，写反只提示不拦截） | 未注册的项目 calc 直接报「未知运动」，必须先注册 |
| MET 与体感不符 | `met` 调数值，或 `intensityOverride` 手工定档（`high`/`mid`/`low`） | 如力训/骑行→high、爬楼→mid |
| 项目专精昵称 | `sportNickname` 改文案 | 影响个人战报与周报的项目昵称签 |
| 成员改名 / 增员 | `nickname` 换新名 + 旧名进 `aliases`；或新增 member 对象 | 重跑即生效 |
| 默认体重（无人填体重的兜底） | 顶层 `defaultWeightKg` | 重跑即生效；单人例外写该成员 `weightKg`，优先级高于默认 |
| 楼层/公里/个数折算 | `convert.climbPerFloorMin`、`convert.kmPerMin[项目]`、`convert.minPerCount[项目]`（口径见第二节） | 谨慎：改了等于换历史口径，归档不回溯重算 |
| 连击成就档位 | `badges.streak` 最后一档保持 **30**（真金火炼）；30 周后胶囊样式固定，成就等级自动每 +10 周 +1 Lv（40→Lv6、50→Lv7…） | 不要加 40：会让口径图多画一档，与胶囊 30+ 固定样式不一致 |

新运动进入**新群默认骨架**时，除 members.json 外还要同步两处静态镜像：`assets/members.sample.json`（`met` / `sportAlias` / `sportNickname`）和 `assets/data.sample.json` 的 `metSnapshot.met`（`sample-schema` 测试强制与 sample 一致）。只给当前群加项目则只改工作区 members.json。周报与个人战报「数据口径说明」的运动分组、专精 chip 均由脚本从 members.json 动态生成，模板无需改；沿用 `h/min/floor/km/count` 这五种单位时脚本也无需改，只有新增量纲才要动 `calc.mjs` 与 `convert`（新增单位须同步 `toMinutes`、preflight 校验与第二节）。

`sportNickname` 不要求唯一：全新专精直接写新字符串；与别的项目共用同一昵称时，专精计数与口径说明 chip 会按昵称合并（如自由活动/自由训练 → 多面手），门槛按合并后的次数算。

MET 拿不准时参照 Compendium（休闲滑雪≈6.0、滑冰≈5.5、滑板≈5.0、徒步≈6.0、爬山≈6.9），**由用户拍板**，不要凭记忆猜。

**伞形项目 vs 具体流派**：像「养生操」这种上位词，`met` 里**只建一条**（默认 2.8），把太极 / 八段锦 / 站桩 / 养生功 写进 `sportAlias` 的别名数组里归并——接龙写哪个都算成「养生操」、合并计次。**不要**给每个流派单独建 MET 条目（会把一类运动拆成四个专精），也**不要**反向把伞形词写成流派的别名（`resolveSport` 双向匹配，会导致「养生操」被静默算成「太极」）。同理：跳操 ← 有氧操 / 健身操。

## 六、禁忌

- 不要手工编辑 `reports/` 下的归档 JSON 与 HTML——重新生成会覆盖。
- 不要删 `aliases`：历史接龙里的旧写法、已归档 `cumulative` 里的旧 key 全靠它归一化。
- 不要把真实 `members.json` 放进 skill 目录或随 skill 打包分享（含成员昵称、体重）；它只应存在于工作区根目录，分享 skill 时只保留 `assets/members.sample.json`。
