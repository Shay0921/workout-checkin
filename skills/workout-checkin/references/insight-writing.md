# AI 洞察文案写法（周报 insights + 个人双行）

> **谁读**：Step 3（补写周报 insights）与 Step 6（个人双行分析）**动笔前必读**。SKILL.md 只规定流程与契约，写作规则全部在本文件——两边不重复，改这里就够了。
>
> **数字的唯一来源**：周报 = `<工作区>/data.json`；个人 = `personal.mjs --digest` 的输出。都是脚本算好的，本文件只规定「怎么用」，不规定「怎么算」。

## 0 总则（两类产物通用，违反任一条即整段重写）

1. **数据在前、判断在后**：一行里至少一个可核对数字，数字后面紧跟判断词（「周均585→613kcal 平稳向上」）。只有形容词没有数字＝不合格；只列数字没有判断＝不合格。**不要求判断句打头**——「17期达标15周…」是合格开头
2. **一个数字只当一次主论点**：跨栏（同一份 insights 的两栏）、跨行（同一人的 full / recent）、跨产物（周报 insights 与个人双行）都算一次
3. **不复用骨架**：写完抠掉数字、昵称、项目名，若剩下的句式与**上期同栏**或**同批他人**高度相似就换
4. **取材封闭**：只引用脚本给出的数字；缺料宁短，**不自己排序、不自己求平均、不自己加减、不自己拆占比**，更不编
5. **零值 / 持平要给判断**：红包 ¥0 要写成「连续 N 期清零 = 全群稳 / 账本封账」这类；只写「本期红包池 ¥0」不合格
6. **允许写短**：确实没有增量就写一句 15 字内的结论，不要为凑长度堆换算

## 1 周报 insights（Step 3）

### 1.1 定位与条数

向 `data.json` 的 `insights` 数组补写 **固定 6 栏 + 条件栏 + 最多 2 条自由栏（共 6–9 条）**，每条 `{title, content}`（content 一句话；序号由模板自动生成从 1 起）。条数、固定 title、顺序、条件栏有无由 render.mjs 硬校验。**条数不是自由裁量**：自由栏候选必须逐个核对、命中必写，流程见 §1.7——连着多期固定 6 条 = 没做候选核对。

**定位铁律：只写模板卡片展示不出来的增量分析与叙事，禁止复读已有模块**——本周之星卡（三星）、回归欢迎卡、里程碑解锁卡、名单 spotlight 胶囊里已有的内容，一律不再重复。每条的标准是「删掉它就少知道一件事」。

### 1.2 固定栏目（title 必须逐字使用枚举值，按序排列）

单一真源为 render.mjs 的 `INSIGHT_TITLES` 枚举，本表为镜像，改枚举时两处同步。

| # | title | 必须回答的问题 |
| - | ----- | ------------- |
| 1 | 达标快报 | 达标**结构**变了没有——谁进、谁出、谁压线过的？（满勤等稳定性亮点并入本栏；请假豁免可带一句） |
| 2 | 趋势解读 | 变化落在**人次**、**单次时长**，还是**强度**上？——直接读 `totalSessions` / `avgMinutesPerSession` / `sportStats[].kcalPerMin`，三个口径哪个在动；上期归档没有这些字段时只判本期结构，不硬造涨跌 |
| 3 | 强度观察 | 哪个项目的**燃效**把整体拉高或拖低——`sportStats[].kcalPerMin` 的高低差有多大，头部项目是高强度在撑还是低强度在占位？（个体之星在「本周之星」卡，此处只写群体面） |
| 4 | 项目版图 | 版图**变宽还是变窄**？集中度往哪边走？ |
| 5 | 能量账本 | 这笔能量换成一个**上期没用过**的生活锚点是什么？（碗米饭、纯脂肪之外自选：通勤、剧集、奶茶、睡眠） |
| 6 | 红包入池 | 本期金额是**意外、趋势，还是清零**？（名单已展示每人红包，不重复点名） |

### 1.3 证据不封闭

上表只规定「必须回答什么」，不限定用哪些字段。`spotlights` / `milestoneCelebrations` / `streakBreaks` / `returnWelcome` / `cumulative.group` / `cumulative.members` 都可取用，也可跨栏拼素材（如达标快报用「请假 + 压线 + 连击」拼一个结构判断）；跨期对照读 `<工作区>/reports/` 上一期归档的 `.json`。问题没有唯一答案，字段才有。

> 派生量一律取自 calc，不自己相除：`totalSessions`（总人次）、`avgMinutesPerSession`（人均单次时长）、`sportStats[].minutes / calories / kcalPerMin`。上期归档若缺这些字段，就只判本期结构；跨期比消耗、时长、人次这三个每期都有的字段。

### 1.4 下笔三步（避免每期都从一个角度写）

1. **先定事实**：一句话写清本期最重要的事，不看视角。如「连续三期零红包 = 全员稳」「达标率跌到 4/10，红包池反弹到 ¥30」「收官周零缺口，账本封账」
2. **过门槛**：视角有适用前提，不满足就换下一个——**不是排班表**：

| 视角 | 看什么 | 前提（不满足则跳过） |
| --- | --- | --- |
| A 结构 | 谁、多少、占比 | 默认可用 |
| B 个体 | 摊到某个人身上是什么量级 | **红包池 > 0**，且人数与上期差异 ≤ 10%；引用 `checkinList` 逐人数字，不自行求平均 |
| C 时间 | 与历史、连续几期比 | 有 ≥ 3 期可比数据 |
| D 机制 | 为什么会这样 | 机制能在数据内验证（项目结构变化、请假、增员），禁止外部猜测 |

3. **平局才取模**：多个视角都过门槛时才用 `期号 mod 4`（0→A、1→B、2→C、3→D）定一个，避免连续两期同视角。**事实永远优先**：全员达标、破纪录、大面积断更这类大事直接跳出视角池

> 门槛反例：红包池 ¥0 的期轮到 B 个体，摊到谁都是 0，荒谬 → B 不通过，跳到 C 按历史跨度下判断。

### 1.5 季节与日期

skill 只有 `weekStart / weekEnd` 两个日期，拿不到天气，也**不要联网查**（历史周天气不可复现，同一份 records 会写出不同文案）。

- 可按日期推季节与节点：跨年、立秋立冬等节气、开学、长假前后、四季轮换——用来写**换季过渡提醒**（落自由栏「时节展望」），如「入秋后户外项目会往室内迁移，下周不妨试试跳操」
- 季节只解释**结构迁移**，且必须在 `sportStats` 里对得上（天冷 → 户外占比降、室内升）；数据与季节预期相反时，写「与季节预期相反」这个**现象**，不解释天气
- **禁止**断言具体天气（降温 5℃、连续阴雨、寒潮）；**禁止**用季节解释涨跌（「总消耗涨 20%，因为天冷了」）；**禁止**用运动量反推季节
- 自检：把句子里的季节词换成对立季节，若仍然通顺 → 这句与季节无关，删掉季节词

### 1.6 条件栏「连击动态」

**插入位置**：第 4 位（「强度观察」之后、「项目版图」之前）。`streakBreaks` 非空时**必须**插入，写断更成员与中断连击数——只反馈结果、不做预警；为空时**禁止**出现（render.mjs 双向强校验，防止凑数）。

文案按 `{N}`（中断连击数 = `streakBreaks[].brokenStreak`）分档选用或仿写，保持语气一致：

- **{N} ≥ 30**（真金火炼档，优先于下一条）：不写「掉档/降档」（30 周后胶囊样式不变、只延续成就等级），按「火焰金熄灭、连击归零」口径写，如「{昵称}的 {N} 连击止步，真金火炼熄灭，重启要从头再来」
- **{N} ≥ 5**（连击资产越大越值得郑重）：遗憾惋惜「{昵称}的 {N} 连击止步本周，差一点点就能再升一级，可惜了」／竞技激将「{昵称} {N} 连击告破，全群最长连击宝座由 {newTop.nickname} 接管（{newTop.streak} 周）」
- **{N} < 5**：温和鼓励「{昵称}此前 {N} 连击，本周中断——下周重启，连击从头再来」／轻松幽默「{昵称}的 {N} 连击本周掉线，重启键就在下次打卡里」
- **兜底**（始终可用）：数据客观「{昵称}中断 {N} 连击（上期 met → 本期未达标/整周请假）」

> 「宝座易主」句式**必须**以 `streakBreaks[].wasTopStreak=true` 为前提（calc 依据上期全群连击对比算出），禁止凭数量臆断；`wasTopStreak=false` 时改用「距离全群最长连击还差 {newTop.streak − N} 周」；newTop 为 null（全群连击清零）时改为「全群连击重回同一起跑线」。

### 1.7 动态扩展池（自由栏候选，0–2 条，逐个核对、命中必写）

| 候选 title | 触发条件 |
| --- | --- |
| 榜单刷新 | 本期出现全群历史之最（最高单期消耗/时长/达标率等，对比 cumulative.group） |
| 项目对比 | 两个项目反差明显（燃效 `kcalPerMin`、人次、时长都在 sportStats 里），不与本周之星卡的个体之星重复，且这组反差是本期**新出现**或方向较上期**反转**的——上期已写过的同组对比不再命中 |
| 士气动员 | 有压线差 1 次或连续缺席成员，且红包栏之外值得单独喊话——**连续性前提**：同一成员连续 ≥ 2 期压线/缺席才算命中，单期普通缺口由红包栏覆盖，不算 |
| 时节展望 | 有换季、节气、跨年、长假等**日期节点**可给下期建议（口径见 1.5） |
| 特别事件 | 节日周、群周年、多人同时里程碑等一次性事件 |
| 惊喜彩蛋 | 数据里的巧合与趣味（两人消耗恰好相同、随机运动彩蛋） |

**标题一律 4 字**（与固定 6 栏同一套版式：2+2 词组，如「达标快报」「士气动员」）。`render.mjs` 硬校验，非 4 字直接退出——卡片标题列是固定宽度，字数不齐会错位。上表是候选而非枚举，可自拟，但必须凑成 4 字。标题只许承诺 skill 做得到的事：本 skill 拿不到天气、只按日期推时节，所以是「时节展望」而不是「天气展望」。

**强制核对流程（每期动笔前必须执行，不可跳过）**：写完固定 6 栏与条件栏后，把上表 6 个候选**逐个**对照本期 `data.json` 与上期归档核对一遍触发条件，不许整体扫一眼就跳过：

1. **命中的候选必须写入**自由栏，不允许以「留待下期」「别的栏已覆盖」为由跳过（「别的栏已覆盖」的正确处理是换素材重写该候选，不是丢弃）；
2. 全部候选都不命中时，才允许只交付固定栏 + 条件栏，且交付说明里必须写明一句「自由栏本期无命中」——留痕证明核对过，而不是默认跳过；
3. 判定模棱两可时**倾向写入**：宁多一条有据的自由栏，不漏一条真实命中；两个候选都命中但只剩 1 个自由栏名额时，选证据更硬的那条；
4. 「宁缺毋滥」约束的是**内容质量**（没有增量素材就不硬凑），不是条数——把「最多 2 条」默认执行成「一律 0 条」是违约，周报条数应随当期事件自然浮动在 6–9 之间，多期连着固定 6 条本身就是没做核对的信号。
5. **增量原则（防钟摆）**：命中判定必须基于**本期特有**的证据——同一命中理由连续出现两期，第二期就不算命中（同一个反差反复讲是复读，不是洞察）。**6 条是基准线，自由栏满额 2 条应当是少数期**（事件密集周才会出现）；若连续 2 期都写满 2 条自由栏，回头逐个候选检查是否把软条件当硬条件用了。

### 1.8 交付前自检

> **只有一条会被脚本硬拦**：与上期同栏骨架重合 ≥ 0.8 → render 报错，0.65–0.8 → 告警。骨架 = 去掉数字与标点后的字符二元组，所以「只换数字」一定被抓。

- 遮住 title 只读 content——能一眼猜到哪一栏 = 合格；发现它同时能放进两栏 = 跨栏复读，删一条。典型翻车是「达标快报里写红包金额」（红包为 0 的期最容易发生）
- 逐条比对 §0 六条总则，尤其第 2、3 条（同一数字是否在两栏都当过主论点；与上期同栏骨架是否雷同）
- **两个最容易塌的栏**：`能量账本`（容易连着几期都写「全群累计运动 X 分钟、消耗 Y kcal，约等于 Z 碗米饭」）与 `强度观察`（容易每期都以「全群人均强度约 X MET」开场）。这两栏写完必须和上期逐字比对，换锚点、换句式

## 2 个人双行（Step 6）

### 2.1 侧车契约

生成前先写 `<工作区>/reports/personal-insights.json`：

```json
{ "issueNo": N, "notes": { "昵称": { "full": "全程分析", "recent": "近 4 周分析" } } }
```

**必须覆盖全部目标成员**（正常交付 = 全部 active 成员；用 `--name` 补生成某一人时，至少覆盖该成员）。期号匹配才渲染；侧车缺失或不全 → 该成员洞察区隐藏（兜底降级，**正常交付不允许出现**），personal.mjs 会打印 ⚠ 警告（含名单），见到必须补写侧车后重跑。

### 2.2 双行格式（先照抄骨架，再填数字）

`full` 回答「这条线走到今天是什么样」，`recent` 回答「最近这几期发生了什么」。**两行的骨架固定**，不要另创散文体：

```
full：{N}期达标{M}周、周均{A}→{B}kcal {趋势词}；{项目1}{次数}次+{项目2}{次数}次（+{项目3}{次数}次），{结构或水平判断}
recent：第{X}周{事件}（{数字}）；{最近状态}{数字}，{判断}
```

下面是标准样例（前两行一组、后两行一组）。`full` 的周均部分有两种合格写法：默认写 `A→B` 箭头（速览每行已直接给出 `周均A→B`）；两端相差不到 2% 时写「周均稳定在 {B}kcal 高位」——同一批十人里统一用同一种，不要混排：

```
17期达标15周、周均585→613kcal 平稳向上；力训21次是最稳主线，连击
第16周请假一周，复出即达标（463kcal）；力训+骑行稳住底盘，练背补位无空转
17期达标16周、周均稳定在1200kcal+ 高位；爬楼15次+羽毛球14次+徒步12次三线并进，强度天花板
第15周部分达标后连升两周（1416→2015kcal），本周296分钟刷新个人纪录，强度重回高位
```

- **`N` / `M` / `A→B` / 项目次数全部来自速览**，一个都不许自己算：`N` = 总期数、`M` = 达标期数、`A→B` = 「周均A→B」、项目次数 = 累计项目 Top3
- **趋势词**看 `A→B` 与近 4 期：上行写「平稳向上 / 稳定抬升」，走平在高位写「高位盘整 / 稳在高位」，回落写「缓慢回落 / 冲高回落」。**不要十个人同一个词**
- **`recent` 必须点名期号**（第 X 周请假 / 部分达标 / 断更 / 连升），这是它与 `full` 最大的区别；括号里放那一期的消耗 kcal
- **取材封闭**：只引用速览给的数字（达标/期数、打卡期数与总次数、请假、缺席、周均 A→B、累计排名、近 4 期均值、峰值、连击、项目 Top3、近 4 期每期消耗/时长/状态）。速览没有的量（逐周项目分布、单周名次）不写，也不自己排序或求平均
- **周均 A→B 的口径**：A = 第 1 期到中点期（ceil(总期数/2)）内有打卡期的平均单期消耗，B = 全程周均。两端都是「截至当时」的累计快照：第 8 期报告看 1–8 期，第 17 期报告看 1–17 期

### 2.3 主论点落点（脚本已分配，不要再自己排）

速览每行末尾的 `▸变化 / 结构 / 水平 + 证据` 决定这个人的**主论点证据**，**照用**：变化 → 近 4 期相对周均的偏离或峰值；结构 → 项目集中度；水平 → 排名、达标全勤或连击。分档与配额由 `scripts/angle.mjs` 确定性算出：**变化、结构两档各最多 `ceil(人数 × 0.4)` 人（10 人 → 4 人）**，其余归水平档兜底（末档不设上限）；变化档内部按证据类型轮转，防止一档全是「近 4 期走高」。用 `--name` 补生成单人时，角度也按全群分配——同一人无论单跑还是全员跑，结论不变。

- **落点跟着骨架走**：`结构`、`水平` 天然能塞进 `full` 第二句（「跳操50%…结构稳但面窄」「累计第1/10…」）；`变化` 若指向某一场高峰/请假复出，写进 `recent` 带期号更自然（「第17周 2014kcal 刷新个人纪录」）——**位置不限，但这条证据必须出现，且只当一次主论点**
- 同一证据不在 `full` 与 `recent` 各说一遍
- 括号里的证据是数字骨架，不是句子：`近4期817(4期)｜周均714（+14%）` → 「最近四周比周均高出约一成四」，不要复述括号
- 「变化」的证据别混着说：近 4 期相对全程周均的偏离、峰值落在最近两期、请假后复出 / 断更。偏离一旦成立，峰值就不再单独报——同一个故事不占两个名额
- 角度与近 4 期事实明显冲突时（标了「复出」但最新一期仍请假）先回看速览核对，不要硬圆
- 仍要横读的一件事：全部 `full` 中若有 3 人以上共用同一句式就重写——配额只保证**角度**不同，不保证**句子**不同。骨架相同是允许的（那是格式），**内容同构**（换了名字数字照样成立）才是要重写的

**硬校验只有一条**：`personal.mjs` 渲染前查同组两行骨架重合 ≥0.8（跨人复制），不过即退出；0.65–0.8 打 ⚠ 告警。判定范围是侧车里全部成员，所以 `--name` 补生成单人时也会发现「这个人撞了别人」。数字是否成立由 §2.2 的取材封闭保证，机器只判骨架。

### 2.4 字数与口径

- 两行各 20–65 字、必须引用真实数字（禁止编造）。骨架本身就要 50 字上下，带一条变化证据会到 60 出头——**超过 65 通常是塞了两条证据，删掉一条而不是压字数删数字**
- **周均口径 = 累计消耗 ÷ 有打卡期数**（速览已按此算，不要拿群期数硬除——请假/未入群会被摊薄）；`A→B` 的 A 是中点检查点的同口径值，直接用，不要重算
- 行尾「无记录 N 期」= 归档里根本没有这个人（未入群 / 改名未归一 / 缺档），**不是缺席**，别写成「缺席 N 期」

## 3 两个产物之间

同一场会话里，周报 insights 与个人双行是**同一批数字的两次写作**，必须互相让路：

- 周报已写进固定栏的事实（断连击、请假复出、破纪录、红包清零），个人双行不再当主论点——最多作为 `recent` 的一句状态交代，且换角度（周报写「谁断了」，个人写「这个人接下来怎么走」）
- 反过来，个人 `full` 里的长期趋势判断，周报 insights 也不复述
- 判断冲突时以周报为准（它是群面结论文档），个人双行只写这个人的个体视角
