# workout-checkin 🏃 运动打卡周报生成器

> 将运动打卡群的接龙原文，自动生成可直接发群的周报（本机有 Chrome 时自动导出长图），以及记录长期成长轨迹的个人报告。
> 无需修改群内接龙习惯，无需手动统计，纯对话式操作：粘贴接龙，说一句「生成周报」即可。

✅ **核心特点**

- **数字全由本地脚本算**：期号、卡路里、红包、排名、连击、徽章、本周之星、趋势对比全部确定性计算，AI 只负责读懂接龙、写文案。同一份接龙跑多少次结果都一致，换任何模型也不变。
- **算数据不烧 token**：数值计算、累计、归档、渲染、出图全部本地完成，0 API 调用；只有翻译接龙和写洞察文案走 AI。
- **历史再长也不变重**：链式累计每期只读上一期归档，出到第 100 期和出第 2 期一样轻。
- **数据只存本地**：成员信息、打卡记录、报告都是本机文件，不上传云端。

适合：运动打卡群群主、管理员、负责每周统计的人。

不适合：需要自动提醒、自动推送、自动催打卡的场景——本工具为**手动触发**的，你贴接龙、它出报告。

## 🌟 它特别在哪

### 1. 数字全由程序计算，AI 只负责“读懂”和“写人话”

期号、打卡次数、卡路里、红包、排名、连击、徽章、本周之星、趋势对比，全部由确定性脚本计算和渲染。换任何模型，这些结果完全一致。

AI 只做三件事：

1. 将接龙文本翻译为结构化打卡记录；
2. 生成数据洞察与个性化文案；
3. 输出群周报；可选生成全员 / 单份个人报告。

### 2. 接龙零要求：群里的习惯不用改

加减号、空格、逗号、顿号混着写可以；序号错乱、重复可以；一条打卡写好几个项目可以；「第三次请假」抵一次运动打卡。

它能处理这些常见噪声：

- `第一次` / `第1次` / `第①次` / `第1️⃣次` / `第二次`
- `小李 自由活动+46分钟+羽毛球+1.85h`
- `小王目标年底60kg` 这种昵称后面带备注的写法
- `yiyi~` 和成员表里的 `yi_yi` 不一致
- 接龙里出现没见过的运动：AI 会先停下来问「这个项目什么强度、消耗大概多少」，确认后才入表，**不瞎猜 MET**。

### 3. 两种报告：群周报 + 个人报告

- **群周报 HTML**：发群里晒。包含达标情况、红包结算、卡路里排行、连击胶囊、本周之星、里程碑庆祝、数据洞察。
- **个人报告 HTML**：一份 HTML 里每人一节，包含全历史累计、六格成就墙、最近 4 周趋势、AI 双行点评、红包账单；也可以只看某个人。

群周报渲染后，本机装有 Chrome/Edge/Chromium/Brave 时会自动导出一张 `<年>-issue<NN>.auto.png`（与页面「保存图片」同尺寸）；没有可用浏览器或导出失败就跳过，不影响 HTML 与手动保存。

两份报告也都可以用浏览器打开，点「保存图片」导出高清长图。
群周报适合发群；个人报告适合自己留存或私发给成员。

### 4. 打卡有激励，不是只有罚款

- **连击胶囊**：连续达标越久，胶囊越“贵”。请假一周清零，没达标也清零。
- **六类成就徽章**：连击、燃脂狂魔、铁人、全能王、常驻居民、自律标兵。
- **每周之星**：破纪录、回归战士、燃效之星、进步之星、消耗之星；同时命中只显示最稀有的一颗。
- **人格标签**：坚持某项运动够多会解锁「专精」，例如 🏊 浪里白条、🏋 撸铁狂人；还会按强度自动点亮「燃烧系 / 均衡系 / 松弛系」。
- **里程碑庆祝**：本周新解锁的徽章会在周报里庆祝，不在每行名单里堆徽章。

### 5. 历史再多，常规周报也不变慢

采用**链式归档**：每一期只读取上一期归档的累计快照，叠加本期增量进行计算（无需扫描全部历史）。出到第100期，常规周报读取路径和第2期一样短。

唯一例外：个人报告的历史速览需要逐期扫归档，但这是本地脚本跑，AI 不参与数值演算。

### 6. 数据本地保存

成员名单、体重、打卡记录、归档报告都存在本机文件里。 不会入库，不上传任何服务器。

需要 Node ≥ 22.20（`skills` CLI 的 engines 要求，低于此版本 CLI 会在启动阶段直接报错）；运行 skill 本身 Node ≥ 20 即可。

```bash
npx skills add Shay0921/workout-checkin -g -y

Node 版本不够时，用兼容旧版 Node 的安装器（1.5.18 是最后一个支持 Node ≥ 18 的版本）：

npx skills@1.5.18 add Shay0921/workout-checkin -g -y
```

### 方式三：手动安装（下载 ZIP）

1. 点仓库右上角 **Code → Download ZIP**
2. 解压后进入解压目录里的 `skills/workout-checkin/`（外层目录名形如 `workout-checkin-main`，`-main` 只是 GitHub 附带的默认分支名），这一层才是 skill 本体（含 `SKILL.md`）
3. 把该文件夹整个复制进 Agent 的技能目录：
   - Claude Code：`~/.claude/skills/`

   - Trae：`~/.trae-cn/skills/`
   - WorkBuddy：`~/.workbuddy/skills/`
   - 其他 Ai Agent 同理

## 💬 怎么用（全程聊天对话，不用记命令）

把 AI 助手打开，像跟群管理员说话一样就行。

### 第一次用：先「建群」

跟 AI 说「**生成运动打卡周报**」或「**统计一下打卡**」，首次使用它会自动进入建群引导，只问你三件事：

1. **群叫什么**——微信群名就行，会显示在周报头部
2. **群里有谁**——最省事的方式：把最近一次接龙原文直接贴给它，名单自动提取；贴完它会补问一句「还有没有人没打卡/没接龙」，把名单补齐
3. **从哪周开始算**——回「上周」或给个日期都行

成员名单这里有一个重要提醒： 
**接龙仅代表参与打卡的人员，不能覆盖全部群成员**。贴完接龙后，它会补问一句「还有没有人没打卡 / 没接龙？」用来补齐完整群成员名单。

其余规则都有默认值，它会列给你看一眼：

- 每周打卡 **3 次**达标
- 差 1 次罚 **¥5**
- 差 2 次或没打卡罚 **¥10**
- 整周请假豁免；部分请假 N 次抵 N 次打卡义务
- 默认体重 60kg
- 常见请假词、20 多种运动的 MET 换算

**不调整就按默认来。**

你还可以顺手补成员体重和性别：

> 小王 52 公斤，女生

体重影响卡路里估算精度；性别不影响卡路里，只影响个人报告头像颜色和文案。

> 注意：每期归档是不可变快照，不会自动重算。后期补体重只对未来期生效。

### 每周出周报：把接龙丢进去

到了周一，把上周的接龙原文直接贴给 AI，说「生成周报」。它会：

1. 读懂每条打卡（格式乱没关系），算好所有数字
2. 产出一份 **HTML 周报**：达标情况、红包结算、卡路里排行、连击胶囊、本周之星、里程碑庆祝、一段人话数据洞察
3. 尝试用本机浏览器自动导出一张长图（`reports/<年>-issue<NN>.auto.png`）；没有可用浏览器就跳过。也可以用浏览器打开报告，点「保存图片」手动导出

如果接龙里出现新运动，它会先问你：

> 桨板是什么强度？消耗大概多少？

确认后才写进配置表，不会猜一个 MET 值糊弄过去。

### 出个人报告：看每个人的长期故事

跟 AI 说「**出个人报告**」生成全员的，或者说「**给小张出一份个人报告**」只看某个人。每人一节，包含：

- 全历史累计（消耗、打卡、达标率、红包账单）
- 六格成就墙 + 累计排行表（可点表头排序）
- 最近 4 周趋势柱状图 + AI 写的两行个性化点评

### 群里有人事变动：直接说人话

| 场景           | 你只需要说                                                   |
| -------------- | ------------------------------------------------------------ |
| 新人进群       | 「群里新来一位，叫小王」                                     |
| 有人退群       | 「小芳退群了」——历史数据保留，统计自动排除                   |
| 有人改名       | 「阿明改名叫大明」——新旧昵称都永久有效，历史累计/连击自动接续 |
| 有人昵称变体   | 「接龙里的 芳芳 就是 小芳」                                  |
| 补充体重性别   | 「小王 52 公斤，女生」（不说就按 60kg 默认，只影响卡路里估算精度） |

### 修改打卡规则

| 想改什么       | 示例                                                         |
| -------------- | ------------------------------------------------------------ |
| 达标线         | 「我们改成每周 4 次达标」                                    |
| 红包档位       | 「差 1 次罚 10 块，差 2 次罚 20」                            |
| 请假词         | 「出差也要算请假」                                           |
| 节假日临时放宽 | 「这周国庆，打卡 2 次就算达标」→ 只对当期生效                |
| 锻炼项目强度   | 「力训其实挺累的，算高强度」——只影响人格标签分档，不影响卡路里 |

## ❓常见问题

### 接龙格式要改吗？

不用。群里有现成习惯就沿用，支持多种格式。
格式样例 A：

```text
#运动打卡# 第 N 周
1. 昵称 第1次 跑步 30min
2. 昵称 第2次 爬楼梯 22层
3. 昵称 游泳 1.5km
4. 昵称 病假
```

也支持群里已有的格式，样例  B：

```text
#接龙
10.12-10.18 每日运动打卡
1. 小李 自由活动+46分钟+羽毛球+1.85h+本周第一次打卡
2. 小王 本周病假
3. 小刘+力训+40分钟+本周第①次打卡
```

只要每行能看出「昵称 + 项目 + 数量单位（或请假原因）」，剩下的交给 AI 和脚本。仅支持文本接龙，图片格式打卡无法解析。

### 为什么卡路里和手环上不一样？

卡路里按 `MET × 体重 × 时长` 算，逐条四舍五入后累加。 

默认体重 60kg；如果成员补了真实体重，后续期数会更准。

另外，每期归档是**不可变快照**，后期改体重不会回头重算历史期。若有需求，可触发重算生成新的归档快照，原有历史会被覆盖。

### 保存图片没反应或失败？

正常交付时会尝试自动出图：本机装有 Chrome/Edge/Chromium/Brave 就输出 `.auto.png`，失败则跳过。手动保存请用**浏览器**打开报告 HTML：

- 若页面提示「保存图片需要联网，请检查网络后重试」，说明导出库没加载成功，联网后重试即可；自动出图不受影响
- Codex、Claude、Trae、Qoder 经过测试均无问题
- WorkBuddy 内置预览不执行页面脚本，点击保存无响应；复制 HTML 到浏览器打开再导出

### 能自动提醒大家打卡吗？

不能。本工具为手动触发模式：需要你贴接龙信息。 不做自动推送、不做自动催打卡、不做定时任务。

### 历史期数多了会不会很慢？

常规周报不会。每期只读上一期归档的累计快照，再叠本期增量。
个人战报的历史速览会扫归档，本地跑脚本，AI 0 token。

### 新运动能不能直接算？

不能直接猜。AI 会先问你项目名、常见写法、强度、消耗大概多少，确认后才写进 MET 表和别名表。
这是为了避免「桨板按跑步算」「攀岩按散步算」这种离谱结果，也避免把散步和徒步混成一类。

你的工作区（运行数据，全部与 skill 目录分离）：

```
你的工作区/
├── members.json        # 群配置——首次使用时引导生成，含真实成员信息
├── records.json        # 每期打卡流水（AI 翻译接龙生成）
├── data.json           # 每期计算结果（calc 生成）
└── reports/
    ├── <年>-issue<NN>.html           # 周报成品
    ├── <年>-issue<NN>.auto.png       # 自动出图（可选）
    ├── <年>-issue<NN>.json           # 归档
    ├── <年>-issue<NN>-personal.html  # 个人战报（按需）
    └── personal-insights.json        # 个人洞察侧车（按需）
```

核心脚本：

| 脚本             | 作用                                                |
| ---------------- | --------------------------------------------------- |
| `preflight.mjs`  | 前置体检：首用判定、配置校验、依赖检查              |
| `calc.mjs`       | 计算引擎：唯一统计真源，链式写累计快照              |
| `cumulative.mjs` | 累计快照共享层：连击、徽章、人格、spotlight、里程碑 |
| `nickname.mjs`   | 昵称归一与别名索引：改名后历史累计按同一人接续     |
| `render.mjs`     | 渲染周报 + 校验 insights + 文案坍缩检测 + 自动归档  |
| `shot.mjs`       | 自动出图：调用本机 Chrome 截取周报卡片，输出 `.auto.png`（零依赖） |
| `personal.mjs`   | 个人战报生成；支持 --digest 参数输出完整历史速览    |
| `angle.mjs`      | 个人双行分析的主论点角度确定性分配                  |
| `text-lint.mjs`  | 文案骨架相似度检测                                  |

## 🔒 隐私

- 成员昵称、体重、性别等真实信息只存在本地工作区的 `members.json`，成员数据不上传服务器或云端数据库。
- 仓库 `.gitignore` 已忽略 `members.json`、`records.json`、`data.json`、`reports/`，克隆或下载本仓库不会拿到任何真实群数据。
- 仓库内所有示例数据均为虚构。
- 统计、计算、归档全部本地完成；自动出图在本机无头浏览器内完成，不上传成员数据。
- 报告 HTML 的截图导出库仅在浏览器端加载，用于手动保存图片。
